# The BMG club release, by MBID: the owner's choice for this disc (2026-11-05:
# "make sure you are choosing the correct album"); row 1 is the 2003 GB release,
# and MusicBrainz's row order is not stable. The read does not depend on it.
pick-release d14a7546-815b-43c6-8af6-35cff6cee1d0 600
expect-dialog none
expect-tracks 2+
# AND THE GATE THAT COUNTING COULD NOT BE. `expect-tracks` is satisfied by
# PLACEHOLDER rows: a disc MusicBrainz cannot identify still fills the table with
# "Track 01".."Track NN" / "Unknown Artist" (track_table.set_placeholder_tracks),
# so the count passed, the abort below never fired, and every rip for the rest of
# the night would have been evidence about a release nobody chose. This asserts
# the fact instead of a symptom of it: a well-formed MusicBrainz release MBID is
# actually held.
expect-identified

# STOP HERE IF THE DISC WAS NOT IDENTIFIED. The section header above has said
# "if this fails, nothing after it can mean anything" since the file was written,
# and until 2026-08-26 it said so and then carried on for six hours — a comment
# where a check belongs, which is the failure `CLAUDE.md` names by that phrase.
#
# What it costs when the check is absent, measured on the rig the same night: the
# release picker was still open at section F's `rip`, the guard correctly refused

abort-if-failed the disc was never identified — the picker did not resolve or no tracks loaded, so every rip after this would be about an unknown release

# --- E2. THE OFFSET OVERRIDE OFF: a drive nobody knows must be refused ------
# TASKS "Permutations the acceptance test still does not run", (a); ruled
# 2026-10-05 (PLANNING.md KDD-41, C4). With the override off, Start goes one of
# two ways. A drive in AccurateRip's drive list gets the list's offset and rips;
# any other drive is REFUSED ("Set up your drive first"), so no rip starts at an
# offset nobody chose. No one line holds on both, and on a listed drive the
# first branch would rewrite the offset section B set, for every rip after it.
#
# So the verb asks the drive list first. ON A LISTED DRIVE (the Pioneer rig is
# one, +667) it records N/A, `unreachable`, and changes nothing: the refusal
# cannot happen on this equipment. That is NOT a pass, and it does not fail the
# run either: the transcript's RESULT line and the closing dialog both count it
# as a step this equipment could not run. ON ANY OTHER DRIVE it turns the
# override off, presses Start, answers the refusal with No (the drive wizard
# must not open in an unattended run), checks no rip started, and puts the
# override back on every path. Seconds, no drive time.
#
# Here, after E, because the refusal is reached only from Start and Start needs
# an identified disc; before F, so the two lines below prove every rip in this
# run reads at the offset section B set.
log --- E2. offset override off: a drive the AccurateRip list does not carry is refused ---
run-size quick
expect-offset-refusal
expect-drive-offset
expect override_read_offset on
