## B. The one code change: a tarball build could not name itself

Found by packaging beta.7 as a source archive for the rig, which is the first
time this fork has been distributed as anything but a clone. The banner was:

```
cyanrip 0.9.4-rc1+platterpus.5-beta.7 (platterpus-fork-g-dirty)
```

**Two false claims in one string.** It names no build — the sha is empty — and
it asserts the tree was modified, on a tree freshly extracted from `git archive`
that provably was not. The build tag is written into every logfile permanently,
so a rip from such a build claims a provenance that resolves to nothing. Had we
shipped it, the J1 rip you are waiting on would have produced an unusable log.

**The cause is the shape this round keeps producing: the failure looked like a
success.** With no `.git`, `git rev-parse` printed nothing to stdout,
`git diff --quiet` exited non-zero so the `-dirty` `printf` ran, and the
enclosing `sh -c` then exited **0** — so meson's `fallback:` never fired. A
command that half-worked was indistinguishable from one that worked. That is
your §C.3 write/read drift and our §C.1 crash-graded-as-refusal for the third
time in two laps.

Fixed with `git archive`'s own `export-subst`: the commit is substituted into
`src/archive-version.txt` and the version command falls back to it when there is
no repository. **The git path is byte-for-byte unchanged**, `-dirty` marking
included. With neither source available the tag is the explicit string
`unknown` — a claim you can act on rather than a malformed one that looks like a
commit.

Verified by building from an extracted archive:

```
$ tar xzf cyanrip-...-92ceeed.tar.gz && cd cyanrip-beta.8-92ceeed
$ meson setup build && ninja -C build && ./build/src/cyanrip --version
cyanrip 0.9.4-rc1+platterpus.5-beta.8 (platterpus-fork-g92ceeed)
```

Revert-proved on the case that actually breaks: with the old command restored
and a build made from an extracted tarball, the banner is `g-dirty` again and
`sc_cli` fails. **A git build passes either way**, so proving this needed the
tarball — reverting in a clone would have shown nothing.

### B.1 Why this is handshake material even though no log line moved

It is build surface, not log format. But the version banner is a string you
parse, and its *value* now differs for a class of build that previously produced
garbage. Under our shared test — **"could the other side notice?"** — it
qualifies. Flagging it is the point; we are not asking you to do anything.

### B.2 The source anchor did NOT move, and that is not the same as "nothing changed"

`HANDSHAKE-SOURCE-ANCHOR` is `8290677bea1a834d`, identical to lap 32. That is
correct and it is also a limitation worth naming rather than letting you infer
from it.

The anchor is a hash over `src/*.c` and `src/*.h`, because its job is making
`file:line` citations checkable. beta.8 changed `src/meson.build` and added
`src/archive-version.txt` — neither is a `.c` or a `.h`. So a **real change to
build behaviour, affecting a string you parse, left the anchor untouched.**

An unchanged anchor means "the cited lines still resolve", not "the source is
unchanged". If you were treating it as a change-detector for our tree, it is not
one. Widening it is round-8 work and we would rather agree the semantics first
than silently change what the number covers.

## F. Tarball vs clone, and one deliberate skip

We now ship a source tarball, so the suite runs in a tree with no git history.
One scenario cannot run there and **says so instead of failing**:

```
SKIP: version_matrix: not a git checkout (source tarball?), so P6's upstream
citations cannot be resolved. P6 is UNVERIFIED here -- run this from a clone
to check it
```

P6 cites upstream commits; a tarball has no history. Reporting that as a failure
made a *correct* build show a red suite on extraction — a false alarm in exactly
the delivery path the fix enabled. **"The check could not run" and "the check
ran and found drift" are different claims**, which is your `none` versus
`unknown (reason)` rule applied to a test result. Meson counts skips separately,
so coverage cannot vanish quietly.

From a clone: **33/33, Skipped 0.** From a tarball: **32/33, Skipped 1.**
