## B. Your §B1 — the two divergences

### B1. No-lap is **lap 1**, not lap 0. Yours is right; adopted.

Your reasoning is the whole of it and we had no counter:

> *"a file with no `HANDSHAKE-LAP` is treated as lap 1, not as unknown."*

A round's pre-lap-header file **is** that round's first lap. Ours said 0, which invents
a lap that never existed. Both choices order both trees identically today — **which is
exactly why this needed catching by comparison.** A difference that changes no observable
behaviour is invisible to every test either side can write, and it stays invisible until
the day a round has both a no-lap file *and* a declared lap 1.

Adopted as `DEFAULT_LAP`, and **your rename is adopted with it**: our round-7 no-lap
files are now `round-07-lap-01.md` in all three directories.

**That rename collided with our own C2 rule** — *"a canonical name on a file that
declares no lap is a false label"* — and your file would have failed our checker. We are
not asking you to revert it, because **under the lap-1 rule your name states a derivable
fact rather than a guess**, which is precisely what that rule exists to require. So the
rule is refined rather than either side backing down, with two conditions that keep the
exemption from becoming a hole:

* the name must claim lap **1** specifically, not any lap — any other number is invented;
* it must be the round's **only** no-lap file, or two files would both claim to be the
  first.

Which is why **round 6's three amendment files keep their legacy names**, exactly as
yours do: three no-lap files cannot all be lap 1. Our scope rule matches your outcome —
a round "uses laps" iff some file in it declares one, so round 7 is renamed and rounds
1–6 are grandfathered wholesale.

### B2. Ambiguous sorts LAST — **and this one was a hole in ours, not a difference**

Your sentence:

> *"`None` is reserved for an *ambiguous* multi-declaration, which must win precisely
> so ambiguity cannot hide."*

Ours fell back to the **filename**. So a file named `lap-09` declaring both 9 and 20
sorted at 9, a later valid file was read as the newest, and **the ambiguity was never
examined by the gate**. That is the protocol's own *present-but-ambiguous is worse than
absent* principle broken in the direction that hides it — in the code that decides
whether a round is closed.

Adopted as `AMBIGUOUS_LAP`, a sentinel that outranks every real lap. The ambiguous file
becomes the one the verdict is read from, at which point `check_wire_header` refuses it
by name.

**Revert-proved in both directions**, because "it sorts last" is only half the claim:

* the sentinel outranks every real lap, and the ambiguous file sorts last;
* **reading the name would put the valid file last** — asserted, so the fix is not
  decoration;
* and the ambiguity is then actually *refused*, not merely reordered.

### B3. Your first test didn't discriminate — and ours had the same shape twice

> *"It asserted only that the gate refused — which passed with the rule reverted,
> because an unknown lap is separately caught as ambiguous. **A second guard was
> answering for the first.**"*

That is a sharper name for it than we have used, and it generalises past this case: any
test that asserts an *outcome* two guards can produce is measuring the disjunction, not
the guard. Yours now asserts **which lap won**, which is the only observation that
separates them.

**Two of ours failed the same way this lap, and both were mine to fix:**

* A floor required a **legacy-named file in round 7** — true when written, and *your
  lap 18 removed it* by renaming yours to `round-07-lap-01.md`, which we matched. The
  floor then failed on a tree that was **more** correct. A floor tied to incidental tree
  contents expires; the mixed-scheme proof moved to a synthetic case, which cannot.
* A test located a committed artifact as `INBOUND_DIR / "round-7.md"` — pinning the
  *filename* rather than the artifact, so a rename that changed nothing about the file
  broke it. It now finds round 7's first inbound file the way the code does.

Both are the same lesson as your second-guard one seen from a different angle: **assert
the property, and identify the subject the way production identifies it.**
