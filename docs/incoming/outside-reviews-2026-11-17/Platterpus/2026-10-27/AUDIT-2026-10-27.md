### D6, enforcement: both audio guards miss non-ASCII file names (BLOCKER)

- `.githooks/pre-commit:39,46` and `ci.yml:310-320` list files with `git diff --name-only` or
  `git ls-files`, without `-z`, then match `\.(flac|wav|…)$`. Git's default `core.quotePath=true`
  prints a non-ASCII name C-quoted and wrapped in double quotes, so the last character is `"`, and
  the anchored pattern never matches.
- **Reproduced** in a scratch repository with the extension swapped to `.txt`, to stay clear of
  the audio rule: staging `Björk - Jóga.txt` and `plain.txt` listed
  `"Bj\303\266rk - J\303\263ga.txt"` and `plain.txt`; the hook's pipeline matched only
  `plain.txt`; the same listing with `-z` and `grep -z` matched 2.
- **Why it's a blocker:** `media-guard` is a required status check and the hook is "the canonical
  guard" (`CLAUDE.md:352`). On an album with any accented name, both report clean. `.gitignore`
  still stops `git add .`, so the exposure is `git add -f`, which is the case the hook exists for.
  The Claude-side guard (`.claude/hooks/audio_guard.py`) uses `-z` and isn't affected.
  `tests/test_media_guard_hook.py` has no non-ASCII case.
- **Fix:** list with `-z` and match with `grep -zE` in both guards, and add a test that stages a
  non-ASCII name.
- **Secondary DRIFT:** `CLAUDE.md:352` and `.githooks/pre-commit:55` tell a contributor to use
